# 实验二：五层校验、自动修正与Cypher成功执行率

状态：设计冻结前草案  
日期：2026-09-11

## 1. 对应的简历表述

实验二验证项目内容2中的两部分：

> 实现语法、写操作、关系方向、LLM验证、Schema验证五层验证机制，并支持自动修正与重试（最多3次），成功执行率达90%。

“成功执行率”的主语定义为：经过生成、五层校验、必要时自动修正和最多3次重试之后的Cypher查询。

实验二不验证项目内容3的“整体问答准确率88%、平均响应时间3.5秒”；那属于后续实验三。

## 2. 必须拆成两个子实验

只对自然生成的查询计算执行率，不能证明五层分别有效；只注入错误查询，又不能证明真实工作流达到90%。因此实验二包含A、B两个子实验。

### 实验二A：受控故障注入

目的：分别验证五层能否检出目标错误、自动修正能否救回查询，以及危险写查询是否始终不会执行。

数据集共35条：

| 类型 | 数量 | 用途 |
|---|---:|---|
| 单层故障 | 25 | 每层5条，候选查询只包含一个预期错误 |
| 组合故障 | 5 | 验证一次查询包含两个错误时能否完整检出和修正 |
| 正确对照 | 5 | 估计误报，正确查询不应被无故修正 |

五类单层故障：

1. `syntax`：缺括号、错误关键字、不完整表达式、未闭合字符串、未定义变量。
2. `write_operation`：`CREATE`、`DELETE`、`SET`、`MERGE`以及数据库管理类写操作。
3. `relationship_direction`：使用真实标签和关系，但关系方向与规范Schema相反。
4. `llm`：语法和Schema均合法，但排序、过滤、聚合、否定条件或题意约束错误。
5. `schema`：未知标签、未知关系、未知节点属性、未知关系属性或不属于题目Schema切片的标签。

每条数据必须包含：

- 唯一ID和自然语言问题；
- 注入故障的`candidate_cypher`；
- `expected_layers`；
- 无歧义的`corrected_reference_cypher`和必要结果列；
- 是否允许关系方向层直接确定性修正；
- 是否预期触发LLM修正；
- 数据集冻结前的人工语义复核结论。

执行路径：

```text
HTTP实验驱动器
  -> 受令牌保护的本机FastAPI实验接口
  -> 注入candidate_cypher到生产validation节点
  -> 五层校验
  -> 必要时生产correction节点修正（最多3次）
  -> 每次修正后重新运行全部五层
  -> 生产execution节点在Neo4j真实执行
  -> 驱动器用独立参考查询判分
```

实验驱动器不得实例化LLM或直接调用DeepSeek API。

### 实验二B：完整工作流成功执行率

目的：验证简历中的“Cypher查询成功执行率达90%”。

- 使用40条冻结自然语言问题；问题集合可以沿用实验一，但不复用实验一模型输出。
- 固定使用当前生产配置：Few-shot `k=3`、五层校验全部启用、最多3次自动修正。
- 每题独立运行3轮，共120次完整后端请求；请求顺序按固定种子随机化。
- 每次必须从自然语言重新生成Cypher，不允许把实验一保存的Cypher作为输入。
- 40题仍是统计聚类单位，重复轮次不能伪装成120个独立问题。

执行路径：

```text
HTTP实验驱动器
  -> 本机FastAPI
  -> 生产Text2Cypher完整子图
  -> 生成 -> 五层校验 -> 修正/重试 -> 执行
  -> 返回validation_trace、correction_history和Neo4j结果
```

## 3. 预先固定的指标

### 实验二A指标

- 分层检出率：目标层正确检出的故障数 / 该层预期故障数。
- 分层误报率：正确对照中被该层错误判定的数量 / 正确对照数。
- 首轮完整检出率：第一次五层校验覆盖全部`expected_layers`的比例。
- 确定性方向修正率：无需LLM重试即可修正并执行的方向错误比例。
- LLM修正触发率和修正成功率。
- 最终语义修复率：最终执行结果与参考查询必要投影等价的故障样本比例。
- 重试分布：0、1、2、3次，以及达到上限仍失败的数量。
- 危险执行数：任何含写操作的候选或仍有阻断错误的查询被执行都记为安全失败。

### 实验二B主指标

`successful_execution`必须同时满足：

1. FastAPI请求和后端模型调用没有未恢复异常；
2. 最终进入生产`execute_cypher`节点；
3. Neo4j真实执行没有异常；
4. 最终输出没有验证或执行错误；
5. 最终语句通过只读检查。

空结果不是执行失败，只要查询合法并在Neo4j无异常完成。

成功执行率：

```text
successful_execution数量 / 全部提交的完整工作流请求数
```

API异常纳入主分母并计为失败，同时额外报告排除基础设施异常后的条件执行率，禁止只报告较高者。

### 实验二B次指标

- 首轮校验通过率；
- 自动修正救回率；
- 最终结果语义正确率；
- 每轮执行成功率和按题多数票成功率；
- 各难度、领域的执行成功率；
- 校验、修正、执行各阶段耗时及总耗时P50/P95；
- 失败原因分布。

## 4. 90%的判定规则

- 主判定使用3轮合计结果：至少108/120次成功，才称“点估计达到90%”。
- 同时完整报告每一轮的`成功数/40`，不得挑选最好的一轮。
- 按40道题聚类Bootstrap计算95%置信区间，避免把三轮重复当成独立样本。
- 补充报告按题多数票结果；多数票至少36/40才达到90%。
- 只有执行成功率达标，不代表Cypher语义正确率也达到90%；两项必须分开报告。
- 五层安全条件为硬约束：危险写查询执行数必须为0。即使总执行率超过90%，出现一次危险执行也不能宣称五层机制验证通过。

## 5. 固定条件

- Schema版本：`ecommerce-v2`。
- 数据库：实验开始前生成只读快照标识和Schema SHA-256。
- 模型：实验启动时由后端健康协议返回并冻结。
- Text2Cypher温度：0.0。
- Few-shot：45条生产模板，B子实验固定`k=3`。
- 最大修正次数：3；最后一次仍有阻断错误时禁止强制执行。
- 并发：默认2，避免大量多轮校验请求造成模型限流。
- 随机种子：20260911。
- 实验接口默认关闭、令牌保护、不出现在OpenAPI文档中；完成后立即关闭。

## 6. 数据质量门槛

正式运行前必须全部通过：

1. ID、问题和候选查询无重复；
2. 所有参考查询只读、语法正确、符合`ecommerce-v2`并能在真实Neo4j执行；
3. 静态层的单层样本只能命中目标层，组合样本必须命中所有目标静态层；
4. LLM语义样本必须在语法、写操作、关系方向和Schema四个静态层全部合法；
5. 正确对照必须通过全部确定性校验并与参考结果等价；
6. 实体值真实存在，预期非空的参考查询必须返回非空结果；
7. 实际发送给模型的问题及A组注入候选，与45条Few-shot模板无完全泄漏和高相似近重复；隐藏参考查询从不进入模型请求，其与模板的相同项只作审计记录；
8. 题目必须明确排序、Top-K、日期边界和数值舍入要求，避免实验一中发现的评分歧义；
9. 写操作候选只能做静态检查和`EXPLAIN`，数据集校验器不得真实执行；
10. 数据集、数据库快照和Schema哈希冻结后，才能发起第一条模型请求。

## 7. 完整性与停止规则

- 每条请求保存唯一后端请求ID、协议版本、数据集哈希、模型、温度、Schema哈希和耗时。
- 保存每轮五层`validation_trace`、每次`correction_history`、最终Cypher、错误、执行状态和结果摘要。
- 检查点逐请求原子写入；中断后只补缺失键，不覆盖已完成记录。
- 协议、数据集、模型、温度、Schema或重复次数不一致时禁止续跑。
- HTTP/API错误、缺失请求ID、重复键、超过3次修正、校验未通过却执行等任一完整性错误出现时，不生成“达标”结论。

## 8. 旧数据和旧结果的处理

旧`text2cypher_benchmark_v1.json`中的22条验证题只作为故障类型设计参考，不直接进入新实验。其候选和参考查询仍混有旧`Product`标签及旧字段大小写，部分单层样本在`ecommerce-v2`下会额外触发Schema错误。

旧`text2cypher_experiments_raw.json`及其报告不参与新实验统计。新实验使用独立数据文件、独立协议版本和独立结果路径。

## 9. 实施顺序

1. 编写35条实验二A数据和40条实验二B清单。
2. 编写独立数据质量校验器并在真实Neo4j上校验。
3. 实现受保护的实验二后端接口和可恢复运行器。
4. 先做不调用模型的协议、边界和安全预检。
5. 经用户确认后再发送数据并正式调用DeepSeek。
6. 完成A、B统计、失败样本复核和报告，随后关闭实验接口。
