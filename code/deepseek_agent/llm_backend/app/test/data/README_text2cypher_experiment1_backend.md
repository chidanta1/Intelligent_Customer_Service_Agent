# 实验一：后端生产路径 Few-shot A/B 协议

## 目的

验证简历中的“Cypher查询生成准确率从无Few-shot的65%提升至85%”。旧的组件级实验一不作为本实验的数据来源。

## 系统边界

```text
HTTP实验驱动器
  -> 本机FastAPI后端
  -> 生产Text2Cypher生成节点
  -> Neo4j向量检索（k=0或k=3）
  -> DeepSeek API
  -> 后端校验并执行生成Cypher
  -> HTTP实验驱动器独立比较参考执行结果
```

实验驱动器不得实例化大模型或调用模型供应商API。后端实验接口默认关闭，启用时必须配置实验令牌，且不出现在OpenAPI文档中。

## 固定条件与变量

- 数据集：`text2cypher_experiment1_v2.json`版本2.0.0，共40题；问题集合沿用v1，参考查询已迁移到`ecommerce-v2`规范Schema。
- A组：`fewshot_k=0`。
- B组：`fewshot_k=3`。
- 每组每题重复3次，共240次后端HTTP请求。
- 使用当前后端模型；Text2Cypher 独立生成/校验模型温度固定为0.0。
- 请求顺序按固定种子随机化，限制并发为4。
- Schema 使用 `ecommerce-v2` 的按题裁剪结果；同一道题的A/B两组使用完全相同的Schema切片。
- 除`fewshot_k`外，问题、Schema切片、模型、温度和评分标准均保持一致。

## 指标

- 语义正确：生成Cypher安全、语法与Schema校验通过、成功执行，且要求的结果投影与参考查询等价。
- 可执行：后端实际执行生成Cypher且未报错。
- API成功：FastAPI返回HTTP 200，并满足协议、模型、温度、Schema版本/哈希和Few-shot数量不变量。
- 显著性：以题目为聚类单位，固定种子进行20,000次Bootstrap，报告准确率提升的95%置信区间。

## 可追溯性

每条记录必须包含唯一后端请求ID、题目、配置、轮次、检索示例、生成Cypher、校验与执行状态、语义判分和耗时。完整性校验失败时不生成最终结论。

2026-09-10已按上述协议完成新实验：3轮合计无Few-shot为52/120（43.33%），有Few-shot为99/120（82.50%），提升39.17个百分点；按题聚类Bootstrap的提升95%区间为25.00～53.33个百分点。240次请求的HTTP/API成功率为100%，但简历中的“65%→85%”未按合计口径复现。完整结果见`../results/text2cypher_experiment1_backend_v2_report.md`，逐请求证据见同目录`text2cypher_experiment1_backend_v2_raw.json`。

结果解释必须保留评分边界：本实验采用固定参考查询的结果投影等价口径；题面未明确说明的舍入、额外限制和并列次级排序会影响绝对分数，但两组采用同一规则，不影响A/B变量隔离。不得把本结果表述成任意Text2Cypher任务的通用准确率。
