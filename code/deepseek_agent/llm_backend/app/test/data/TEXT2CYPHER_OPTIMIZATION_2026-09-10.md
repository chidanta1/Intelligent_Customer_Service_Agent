# Text2Cypher 六项优化实施记录

日期：2026-09-10

## 已实施

1. Schema统一：以增量、幂等迁移增加 `ecommerce-v2` 规范标签、字段、类型、领域和版本标记；保留原标签与字段以兼容已有功能。
2. Few-shot修复：原25条示例全部改写为规范Schema，并加入完整的领域、查询类型、难度、版本和依赖元数据。
3. 检索过滤：先确定 `domain/query_type`，再执行向量召回；仅保留活动、同版本、同领域且当前Schema切片可支持的示例。
4. Schema裁剪：生成节点按问题只提供相关节点、字段、关系方向和关系属性，不再把整库结构塞入提示词。
5. 困难与覆盖模板：新增20条模板，覆盖时间聚合、空值/反向模式、聚合后过滤、自连接、多跳销售额、客户—评价—商品及过滤后单实体示例不足等结构。
6. 低温生成：Text2Cypher独立模型温度改为0.0；客服路由、规划和总结仍使用原配置，避免扩大改动范围。

## 校验结果

- Schema迁移：234/234业务节点版本和领域正确；675/675业务关系版本和领域正确；285/285条 `CONTAINS` 关系具备FLOAT/INTEGER/FLOAT规范字段。
- Few-shot审计：45条模板已纳入自动语法、Schema、元数据和真实Neo4j执行审计。
- 数据集审计：40条生成题和22条校验题通过；Few-shot精确问题泄漏、精确Cypher泄漏和近重复均为0。
- 单元回归：15/15通过。
- 服务状态：FastAPI `/health` 返回 `status=ok`，首页可访问。

## 重新实验结果与证据边界

六项优化后已通过受令牌保护的本机FastAPI实验接口重新运行实验一。40题、每组每题3轮，共240次后端请求全部获得HTTP 200且具有唯一后端请求ID；模型调用由后端生产Text2Cypher生成节点发起，实验驱动器未直接调用模型供应商。

- 无Few-shot：52/120（43.33%），可执行118/120（98.33%）。
- 有Few-shot：99/120（82.50%），可执行120/120（100.00%）。
- 提升：39.17个百分点；按40题聚类Bootstrap的95%区间为25.00～53.33个百分点。
- 按每题3轮多数票：19/40（47.50%）→34/40（85.00%）。

因此可以证明Few-shot在本地固定数据快照和严格参考投影口径下带来稳定正向提升，但不能证明简历中的“65%→85%”得到复现。绝对准确率还受参考查询中舍入、限制条数和并列排序等评分约束影响；完整口径、限制和逐请求证据见`../results/text2cypher_experiment1_backend_v2_report.md`与`../results/text2cypher_experiment1_backend_v2_raw.json`。
